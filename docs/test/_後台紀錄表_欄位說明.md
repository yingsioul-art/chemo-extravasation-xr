# 使用者後台紀錄表｜欄位說明（2026-09-30）

> 學員在網頁版各站（首頁、預防與辨識、外滲當下怎麼做、查詢站、發生外滲後的指導、紀錄與追蹤、360° 網頁 VR、前後測）的操作，由 `docs/assets/js/track.js` 批次送到前後測同一個 Apps Script（`payload.type = "activity"`），寫入試算表「外滲XR_前後測成績」的工作表 **`activity`**（第一次收到資料時自動建立標題列）。
> 不收姓名、不收病人資料；辨識只用學員代號（手機末 4 碼＿生日月日，與前後測同一組，首頁輸入一次）。

## 三、樞紐分析 3 個範例（Google 試算表：插入 → 樞紐分析表，資料範圍選 activity 整張）

1. **各站完成率**
   - 列：`頁面`；值：`代號` 計數不重複（COUNTUNIQUE）
   - 篩選：`動作` ＝ enter → 得「到訪人數」；另做一張篩選 `動作` ＝ complete → 「完成人數」；兩者相除＝完成率。
2. **最常錯的題**
   - 篩選：`動作` ＝ answer；列：`頁面`、`項目`；值：`對錯` 的 AVERAGE（＝答對率）與 COUNTA（作答次數）
   - 以答對率由小到大排序；再加 `嘗試次數` 的 MAX 看有沒有人反覆錯。
3. **平均停留時間**
   - 篩選：`動作` ＝ leave；列：`頁面`；值：`停留秒數` 的 AVERAGE 與 MEDIAN
   - 想看手機 vs 電腦：欄加 `裝置`。

## 四、注意

- 送出方式是「至少送一次」：網路不穩時同一筆可能重送，Apps Script 以 `事件ID` 去重（比對最近 2000 列）。
- 學員關閉瀏覽器前沒送出的事件會存在本機，下次開頁自動補送。
- 程式：前端 `docs/assets/js/track.js`；後端 `docs/test/_Code_v3.gs`（部署步驟見 `_AppsScript部署步驟.md` 第八節）。
